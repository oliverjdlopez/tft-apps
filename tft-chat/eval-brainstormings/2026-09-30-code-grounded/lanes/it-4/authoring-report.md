# IT-4 dataset authoring report

Authored six active dataset items: IT-4-C01 through IT-4-C06. Each input preserves the reconciled original player question as its lead and adds the case's concrete stars, item allocations, trait/stratum scope and investigation constraints. The inputs make the supported approximation explicit for globally unobservable restrictions, including the one-radiant question, special-item and budget equality, frontline role and Eternal Pact's linked ally.

The deterministic checks follow existing tool paths without encoding brittle nested cohort arguments. The cases check stored-name resolution where relevant, support discovery through `query_cohort`, and `compare_cohorts` for the central package contrasts. These checks demonstrate tool invocation only; they do not establish successful results or correct comparisons. No display tool or redundant context call is required.

The quality requirements demand case-specific joint allocations, holder guards, support counts, placement/top-four/win outcomes, common-stratum interpretation and honest handling of suppression and uncertainty. They do not select an expected winner or turn historical numbers into gold answers. Metadata uses `grading_scope: investigation_behavior_and_answer_coverage` and `numeric_ground_truth_verified: false`: the native judge receives bounded trace and presentation evidence, not full analytical tool outputs. Exact numerical verification still requires a frozen aggregate reference or a full-trace audit.

Remaining preparation gaps include external verification of a stable Set 18 standard-ranked scope, dataset revision and collection provenance; public cohort floors may suppress restrictive cells. The available filters cannot establish global item counts, exact whole-board equipment equality, economic access, a guaranteed exhaustive roster, hidden trait/partner mechanics or causal effects. This work does not establish that the scope is ready or that observations were collected.

Validation performed: reviewed `dataset_registration.py`, the natural item schema, trace evaluation and execution-evidence construction; parsed the JSON and checked case IDs/order, original-question prefixes, metadata grading caveat, status and requirement presence; exercised every deterministic trace check using the existing brainstorming validator's positive and negative synthetic witnesses with `PYTHONDONTWRITEBYTECODE=1`; confirmed importer normalization and semantic validators in memory. The lane guide describes OR alternatives as a list in `check.value`, while current `evals/utils.py` accepts a scalar `value` or a plural `values` list; this dataset uses scalar checks and avoids that discrepancy. No registration, database query, web lookup, model run or live evaluation was performed.
