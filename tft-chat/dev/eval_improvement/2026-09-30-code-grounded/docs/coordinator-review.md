# Coordinator reconciliation and review

The original 69 questions were retained, with two explicit website-panel adaptations and a visible single-scope qualification for the Cassiopeia before/after question. Each lane received its coordinator-authored case handoff before dataset authoring was delegated. The final JSON keeps the stable source IDs, original status and proposal lineage; the historical answers are not numerical gold.

## Decisions that change how the cases are benchmarked

| Original reference request | ChatTFT interpretation |
| --- | --- |
| Compare builds or boards | Explicit observed holder/build or joint unit/trait populations; board counts, mean placement, top-four/win outcomes, overlap and available uncertainty. |
| Find composition cores | Bounded candidate discovery followed by joint membership checks; individual partner frequencies do not establish a recurring core. |
| Ordinary, artifact-free, equally expensive boards | Named holder builds and inspected inventory/investment slices; stronger whole-board claims remain unverified unless the actual observations establish them. |
| Main tank or carry role | Declared star and named item investment; combat damage, absorbed damage and player intent are unavailable. |
| Without a trait | The complement of active-trait boards within the shared family; an existing inactive row is different from a missing row. |
| Exact roster | Require all N distinct identities, then use a reportable N-record grouped query row for that row's outcomes. A partial core or level alone does not establish closure. This does not supply a capacity filter or comparison confidence interval. |
| Top-four composition recurrence | Complete reportable placement cells or comparison histograms; do not sum suppressed cells or confuse recurrence among top fours with a top-four success rate. |
| Before/after patch performance | One selected scope supports the current comparison; temporal conclusions need separately supplied compatible evidence. |

## Content corrections during dataset review

- Made mandatory stars, items, named core members and supported approximations visible in player input rather than hiding them only in grading requirements.
- Corrected the Nidalee emblem comparison to a shared ordinary pair plus either the emblem or an ordinary third item, avoiding an accidental four-item build.
- Preserved the emblem's equipment slot in Sett, Master Yi and other holder cases; exact holder trios require occurrence-bound evidence or a one-copy guard across all stars.
- Removed implementation syntax and duplicated scenario prose from player inputs. Corrected the Kha'Zix/Fiddlesticks wording to distinguish the itemized carry from the tank.
- Restored shared Ahri/Sett and Ahri/Morgana package investment requirements where an initial lane draft specified only level and presence.
- Replaced unnecessary mandatory tool paths with supported alternatives where the same investigation can use grouped queries, loadouts or contextual deltas. Kept stronger checks where the requested complement or uncertainty requires them.
- Allowed the exact stored-roster grouped-row route for constructed trait packages and the two adapted composition panels. Fully specified stars plus roster closure can also establish the complete stored star vector. Neither conclusion extends automatically to broader comparison populations.
- Corrected a trait requirement that could have conflated six contributors with a six-unit board. Medal tiers, contributor counts, unit-record counts, player level and occupied capacity remain distinct.
- Standardized provenance, Set 18 standard-ranked context, data-readiness flags and the numerical-grading limitation across lane files.

## What the validation establishes

The [machine-readable validation report](../validation/dataset-validation.json) records import normalization, semantic validation, authored argument-schema checks and synthetic positive/negative trace witnesses. The combined file is the ordered concatenation of lane files. This validates definitions and assertion behavior; it does not execute gameplay investigations.

The original research and inspected source/documentation/evaluation/test files are checked against the initial SHA-256 baseline. The two pre-existing unrelated working-tree changes remain outside the task. No application source, original research, runtime data, Langfuse catalog or snapshot was intentionally modified.

The [capability contract](capabilities.md) and [validation/use guide](validation-and-use.md) describe the remaining evidence requirements. Import-compatible definitions are complete; a measured numerical benchmark still needs a suitable frozen population and adequate access to analytical outputs during grading.
